# MaPLe 门控改进 · 组内汇报

这份文档给组员看，把论文原理、我们改了什么、实验怎么跑的、数据什么样、结果怎么解释、后面打算怎么改，一次讲清楚。结论放在最前面：我们把 MaPLe 复现出来了，在它上面加了一个可学习的门控，跑完六个数据集，结果不支持"门控普遍有用"。但这个负结果我们查清楚了原因，作业和展示都站得住。

## 一、MaPLe 在解决什么问题

先讲两句背景。CLIP 这种大模型直接全量微调很贵，还容易破坏它本来学到的通用能力。所以有一类方法叫 prompt learning：模型完全冻结，只训练几个额外拼在输入上的可学习 token，让模型看到更适合下游任务的提示，不动它原来的权重。

MaPLe（CVPR 2023）在这条线上又往前走了一步。之前的 CoOp 只在文本侧加 prompt，VPT 只在视觉侧加，MaPLe 两边都加，而且让两边的浅层 prompt 互相"翻译"：文本浅层 prompt 经过一个线性层投影成视觉浅层 prompt，视觉浅层 prompt 也投影回文本侧。到了深层，每个 Transformer block 都有自己的 prompt，文本深层 prompt 会再被投影到视觉空间，当作视觉深层的 prompt 来用。我们改的就是这最后一步。

深层视觉 prompt 的生成，原论文是这么写的：

```text
z_l = F_l(P_t_l)
```

F_l 是第 l 层的线性投影，P_t_l 是第 l 层的深层文本 prompt，z_l 就是喂给视觉 Transformer 第 l 层的深层视觉 prompt。ViT-B/16 配置下 PROMPT_DEPTH=9，对应 8 组这样的深层投影：第 0 层是浅层耦合，剩下 8 层各有一个。

## 二、我们加了什么

改动很小：在 z_l 算出来之后、送进视觉 Transformer 之前，乘一个门控 g_l：

```text
g_l = 1 + 0.5 * tanh(alpha_l)
P_v_l = g_l * z_l
```

alpha_l 是我们新加的可学习参数，初始化为 0，所以一开始 g_l 恒等于 1，训练的第一步和原版 MaPLe 完全一样。tanh 把它压在 (0.5, 1.5) 区间里，不会跑飞。

我们做了三个开关：

- none：不加门控，就是原版，也是默认值。
- scalar：每一层只学一个标量，整层所有通道、所有 token 一起缩放，一共多 8 个参数。
- channel：每一层学一个 768 维的向量（ViT-B/16 的视觉宽度是 768），不同通道各管各的，同一层所有 prompt token 共享，一共多 8 × 768 = 6144 个参数。

要强调一点：这是按层共享的静态门控，它不依赖输入的图片，所有图片用同一套门控。它不是"看着每张图动态生成权重"的条件门控，这两件事差别很大，报告里我们一直分得很清。

当时为什么想做这个？直觉是：深层跨模态投影到底该给视觉 prompt 多大权重、哪些通道更重要，也许学一个缩放因子能影响 base 类和 novel 类之间的权衡。但一开始我们就知道一个理论上的坑：z = g ⊙ (W x + b) 这种形式，静态的 g 可以整体吸收进新的 W' = diag(g) W 和 b' = g ⊙ b 里，严格来说并没有扩大模型的表达空间。它能产生效果，只能来自改变优化轨迹，而不是让模型"更能装"。这一点我们从头到尾没有回避。

## 三、实验怎么做的

环境是 AutoDL 上的 RTX 3090（24G），PyTorch 2.1.2。所有主实验用同一套配置：ViT-B/16、16-shot、每类 2 个 prompt token（N_CTX=2）、PROMPT_DEPTH=9、训练 5 个 epoch、SGD 学习率 0.0035、momentum 0.9、weight decay 0.0005、1 个 epoch warmup、fp16。CLIP 的文本和图像编码器全程冻结，只训练 prompt 和门控。

数据集六个：OxfordPets、DTD、Caltech101、Flowers102、EuroSAT、FGVCAircraft。每个数据集上 none / scalar / channel 各跑三个种子（1/2/3），同一个 epoch-5 checkpoint 分别评 Base 类和 Novel 类，算 Harmonic Mean。主实验一共 6 数据集 × 3 模式 × 3 种子 = 54 组正式训练，再算上消融和诊断就更多了。

指标除了准确率，还记了可训练参数量、训练时间和显存峰值，方便报告里写开销。

发现 FGVCAircraft 上 channel 崩得很厉害之后，我们又补了三组诊断，都提前把要查什么写清楚，没有一边跑一边改超参：

- D1：把 channel 的门控 alpha 冻结成 0（门控恒等于 1），和同种子 none 比 checkpoint。三个种子的 330 个共享张量逐位相同，说明门控等于 1 时前向路径和原版没有区别，不是代码写错了。
- D2：单独把门控的学习率乘 0.1 或 10，其余参数不动。FGVCAircraft 的崩溃在这两个乘子下都消失了，唯独默认 1.0 崩；EuroSAT 三个乘子都稳定。
- D3：FGVCAircraft channel seed 2 逐 epoch 记门控的偏离程度和梯度。精度在第 2 个 epoch 崩，但那时门控偏离 1 只有 5.2e-4，几乎还是恒等，门控梯度也比其他参数小两三个数量级。

## 五、这些数字说明什么

直接说结论：六个数据集看下来，门控没有普遍提升。scalar 在 DTD 上平均 +1.36 个点，channel 在 EuroSAT 上平均 +1.28 个点，看着不错，但同一个改动在其他数据集上就是负的，而且 DTD 那个 +1.36 的配对差标准差有 2.30，主要靠 seed 3 的 +3.99 拉起来，不能当稳定收益写。

最扎眼的是 FGVCAircraft 的 channel：平均 HM 从 36.20 掉到 24.32，标准差 10.20，崩在 seed 2/3。三组诊断把它定性为优化轨迹问题而不是实现 bug——门控在最崩的时候还几乎等于 1，梯度也很小，但就是这么一点微小的重参数化，改变了这个低数据、细粒度任务上的优化走向。把门控学习率调大或调小崩溃就消失，说明它对学习率非单调敏感。

冻结投影的消融也很有意思：把 8 个深层投影冻住、只训练门控，channel 在 OxfordPets 仍然会改变结果（相对冻结 none 是 -0.69），说明"代数上能被吸收"不等于"有限步优化里走的是同一条路"。但它也没变成稳定增益，进一步说明这条路不太行得通。

给组员的一句话：我们验证了一个合理但失败的假设，而且把失败原因查到了优化动力学层面。这门课要的是复现、改进、分析，这三样我们都齐了。

## 六、后面打算怎么改

现在的判断是静态门控这条路线基本到头了，因为它绕不开参数冗余。如果还要继续做，更有希望的方向是把门控改成"输入条件"的：让门控由当前图片的特征生成，这样 g 依赖输入，就没法被静态吸收进 W 和 b，才真正增加表达能力。这是下一步最值得试的改动。

动手之前有几个小而必要的补强：

- 把 gate 学习率消融补成正式消融，顺便试 gate 的 weight decay 和正则。
- 补纯 fp32 / AMP 两条数值路径的验证，现在正式实验走的是原版 fp16。
- 种子从 3 个加到 5 个，至少在最敏感的数据集上，看波动到底有多大。
- 相关工作再查一轮。SSF（NeurIPS 2022）已经有"静态通道缩放并折叠进前一线性层"的做法，所以我们报告里定位成"研究这种重参数化的优化影响"，不碰"首创"两个字。

数据和 checkpoint 都在 AutoDL 上，GitHub 只放代码和聚合结果，不放权重、原始日志和数据集。回退到原版很简单，配置里 GATE_TYPE=none 就行，原始基线一直没动过。
