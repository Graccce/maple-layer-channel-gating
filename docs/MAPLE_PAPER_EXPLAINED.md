# MaPLe 原论文梳理

> 论文：Muhammad Uzair Khattak, Hanoona Rasheed, Muhammad Maaz, Salman Khan, Fahad Shahbaz Khan.
> **MaPLe: Multi-modal Prompt Learning**. CVPR 2023. arXiv:2210.03117。
> 官方代码：https://github.com/muzairkhattak/multimodal-prompt-learning
>
> 本文按"背景 → 问题 → 方法 → 架构 → 实验 → 局限"的顺序梳理原论文。文中的数字来自论文正文（arXiv v3），
> 代码细节来自本仓库保留的官方实现（`trainers/maple.py`、`clip/model.py`）。

---

## 1. 一句话概括

MaPLe 在冻结的 CLIP 上**同时给文本编码器和图像编码器加可学习的提示（prompt）**，并且图像侧的提示不是单独学，
而是**由文本侧提示经过一个线性层"翻译"得到**；这种耦合在 Transformer 的前 J 层逐层进行。这样只训练约 3.55M 个参数，
就能让 CLIP 更好地适配下游任务，同时在没见过的新类别上也泛化得更好。

---

## 2. 背景知识

### 2.1 CLIP 是怎么做分类的

CLIP 由一个**图像编码器**（本文用 ViT-B/16）和一个**文本编码器**（Transformer）组成，在 4 亿对网络图文数据上做对比学习，
把图像和文本映射到同一个特征空间。

做零样本分类时：

1. 为每个类别写一句手工模板，比如 `a photo of a {类别名}.`，送进文本编码器，得到每个类别的文本特征 `z_i`；
2. 图片送进图像编码器，得到图像特征 `x`；
3. 计算图像特征和每个类别文本特征的余弦相似度，最大的那个就是预测类别：

```
p(y | x) = exp(sim(x, z_y) / τ) / Σ_i exp(sim(x, z_i) / τ)
```

优点是**不用训练就能识别任意类别**（开放词汇）。缺点是：

- 效果对模板措辞很敏感，"a photo of a" 和 "a photo of the" 可能差好几个点，需要人工调模板；
- 在和预训练数据差别大的领域（卫星图、纹理、飞机型号）上表现不好。

### 2.2 为什么不直接微调 CLIP

- 模型太大，下游任务往往只有少量样本（few-shot，每类 16 张），全量微调容易过拟合；
- 微调会**破坏预训练学到的通用知识**，让模型在新类别上的零样本能力下降；
- 线性探测（只训练最后的分类层）则直接丢掉了零样本能力。

### 2.3 提示学习（Prompt Learning）

借鉴 NLP，把 CLIP 整体冻结，只训练少量拼接在输入里的"软提示"向量（不是真实的词，而是可学习的连续向量）。
在 MaPLe 之前的代表工作：

| 方法 | 在哪加提示 | 特点 | 问题 |
|---|---|---|---|
| **CoOp**（IJCV 2022） | 只在文本输入层 | 把手工模板换成可学习向量 `[V1][V2]...[类别名]` | 在训练过的"基类"上很好，在新类上严重过拟合（11 数据集平均新类 63.22%，比零样本 CLIP 的 74.22% 还低） |
| **CoCoOp**（CVPR 2022） | 只在文本输入层 | 用一个小网络根据每张图片生成条件化的提示 | 新类泛化变好，但基类精度下降；每张图都要重新编码一遍文本，推理很慢 |
| **VPT**（ECCV 2022） | 只在视觉侧 | 在 ViT 各层插入可学习 token | 只适配了视觉一侧 |

### 2.4 评价设置：Base-to-Novel 泛化

这是本项目主要使用的设置：

- 把每个数据集的类别对半分成**基类（Base）**和**新类（Novel）**；
- **只用基类**的少量样本（每类 16 张）训练；
- 测试时分别在基类和新类上评估准确率，再计算调和平均数：

```
HM = 2 × Base × Novel / (Base + Novel)
```

HM 同时惩罚"基类好、新类差"的情况，所以它衡量的是**在适配下游任务的同时，有没有丢掉泛化能力**。

## 3. 论文要解决的问题

论文的核心观点是：**以前的方法只在 CLIP 的一个分支（文本或视觉）加提示，这是不完整的。**

CLIP 的分类依赖图像特征和文本特征**对齐**。如果只调文本侧（CoOp、CoCoOp），图像特征完全不变，
只能单方面移动文本特征去迁就固定的图像特征；只调视觉侧（VPT）则反过来。作者认为两侧都应该能动，
才能在下游任务上把两种表示调到最合适的对齐状态。论文用 t-SNE 可视化说明：CLIP、CoOp、CoCoOp 的图像特征是一模一样的
（它们都不改视觉侧），而 MaPLe 的图像特征在 DTD、EuroSAT、UCF101 上类别之间分得更开。

但"两侧都加提示"还不够：如果两侧提示**各学各的**（论文称为 Independent V-L Prompting），两个分支在学习过程中没有交互，
效果提升有限。所以还需要让两侧提示**互相耦合**。

## 4. 三个创新点

论文原文列出的三点贡献：

### 创新 1：多模态提示学习

第一个在 CLIP 的**文本和视觉两个分支同时**学习提示的方法（论文原话是 "to the best of our knowledge, the first"）。

### 创新 2：视觉-语言耦合函数（V-L Coupling Function）

视觉提示**不独立学习**，而是由文本提示通过一个线性层映射得到：

```
P̃_k = F_k(P_k)        F_k: 512 维 → 768 维的线性层
```

- `P_k`：第 k 层的文本提示（文本侧宽度 d_l = 512）
- `P̃_k`：第 k 层的视觉提示（视觉侧宽度 d_v = 768）

作用：

- 把两个模态"绑"在一起，视觉提示被显式地条件化在文本提示上；
- 训练时，视觉侧的梯度会通过 `F_k` **反向传到文本提示上**，两个分支互相影响（论文称为 mutual synergy，互相协同），
  而不是各自找一个单模态的最优解。

### 创新 3：深层提示（Deep / Hierarchical Prompting）

提示不只加在输入层，而是在**前 J 层 Transformer 每层都放一组新的提示**（J=9，ViT-B/16 共 12 层）。
每进入一层，就把上一层输出中提示位置的 token 丢掉，换上这一层自己的新提示。
这样可以在不同特征层次上逐层调整表示。论文消融显示，性能大体随深度增加而提升，在 J=9 时最好。

## 5. 模型架构

### 5.1 整体结构图

```
                    ┌───────────────── 文本分支（冻结） ─────────────────┐
 "a photo of a cat" │                                                   │
   词嵌入 W0 ──────►│ [P0, W0] → L1 → [P1, W1] → L2 → ... → LJ → ... → LK │──► TextProj ──► z (512)
                    └───────▲──────────────▲─────────────────────────────┘                    │
                            │P0            │P1 ... P_{J-1}  (可学习，每层一组)                  │
                            │              │                                                   │
                       ┌────┴───┐     ┌────┴───┐                                          余弦相似度
                       │  F_0   │     │ F_1..  │   耦合函数：线性层 512 → 768（可学习）        │ ÷ τ
                       └────┬───┘     └────┬───┘                                               ▼
                            │P̃0           │P̃1 ... P̃_{J-1}                                  softmax
                    ┌───────▼──────────────▼─────────────────────────────┐                    ▲
   图像 → patch 嵌入│ [c, E0, P̃0] → V1 → [c, E1, P̃1] → V2 → ... → VK     │──► ImageProj ──► x (512)
                    └───────────────── 图像分支（冻结） ─────────────────┘
```

**只有四样东西是可训练的**：文本提示 `P0 ... P_{J-1}`、耦合函数 `F_0 ... F_{J-1}`。
CLIP 的文本编码器、图像编码器、两个投影头全部冻结。

### 5.2 逐层公式

**文本分支**（`b` 个提示 token，`L_i` 是第 i 个文本 Transformer 层）：

```
[ _, W_i] = L_i([P_{i-1}, W_{i-1}])        i = 1, ..., J      （每层丢掉旧提示，换新的 P）
[P_j, W_j] = L_j([P_{j-1}, W_{j-1}])       j = J+1, ..., K    （J 层之后提示照常往后传）
z = TextProj(w_K^N)                                            （取最后一个 token：EOS）
```

**图像分支**（`c` 是 CLS token，`E` 是 patch token）：

```
[c_i, E_i, _] = V_i([c_{i-1}, E_{i-1}, F_{i-1}(P_{i-1})])    i = 1, ..., J
[c_j, E_j, P̃_j] = V_j([c_{j-1}, E_{j-1}, P̃_{j-1}])          j = J+1, ..., K
x = ImageProj(c_K)
```

当 J=1 时，文本侧退化成 CoOp（只在输入层加提示）。

### 5.3 具体配置（ViT-B/16）

| 项目 | 取值 |
|---|---|
| 主干 | CLIP ViT-B/16，12 层；文本宽度 512，视觉宽度 768，公共空间 512 |
| 提示长度 b（每层每侧的 token 数） | 2（代码中 `N_CTX=2`） |
| 提示深度 J | 9（代码中 `PROMPT_DEPTH=9`） |
| 第一层文本提示的初始化 | 用 "a photo of a" 的词嵌入初始化；深层提示用正态分布随机初始化 |
| 优化 | SGD，学习率 0.0035，batch size 4，5 个 epoch，每类 16 张样本 |
| 可训练参数 | 约 3.55M，相当于 CLIP 的 2.85% |

可训练参数的构成（本仓库可以精确核对到 3,555,072）：

| 部分 | 数量 | 参数量 |
|---|---|---:|
| 第 0 层文本提示 | 2 × 512 | 1,024 |
| 深层文本提示 | 8 层 × 2 × 512 | 8,192 |
| 浅层耦合函数 F_0 | 512 × 768 + 768 | 393,984 |
| 深层耦合函数 F_1..F_8 | 8 × (512 × 768 + 768) | 3,151,872 |
| **合计** | | **3,555,072** |

可以看出，**99.7% 的参数在耦合函数里**，提示本身只有 9K 多个参数。

### 5.4 代码里的对应位置

| 论文概念 | 代码 |
|---|---|
| 文本提示 P_0 | `MultiModalPromptLearner.ctx`（`trainers/maple.py`） |
| 深层文本提示 P_1..P_8 | `compound_prompts_text` |
| 浅层耦合函数 F_0 | `self.proj = nn.Linear(512, 768)` |
| 深层耦合函数 F_1..F_8 | `compound_prompt_projections`（8 个独立的线性层） |
| 每层替换文本提示 | `clip/model.py` 中 `ResidualAttentionBlock_MaPLe`，`text_layer=True` 分支：替换位置 1 到 1+N_CTX 的 token |
| 每层替换视觉提示 | 同一个类，视觉分支：去掉序列末尾 N_CTX 个旧 token，拼接新的视觉提示 |

## 6. 实验结果

### 6.1 Base-to-Novel 泛化（11 个数据集平均，论文表 3a）

| 方法 | Base | Novel | HM |
|---|---:|---:|---:|
| CLIP（零样本） | 69.34 | 74.22 | 71.70 |
| CoOp | 82.69 | 63.22 | 71.66 |
| CoCoOp | 80.47 | 71.69 | 75.83 |
| **MaPLe** | **82.28** | **75.14** | **78.55** |
| 相对 CoCoOp | +1.81 | +3.45 | +2.72 |

要点：

- MaPLe 在新类上平均 75.14%，**超过了零样本 CLIP（74.22%）**；CoOp 和 CoCoOp 的新类都比零样本 CLIP 低；
- 在基类上基本保持了 CoOp 的水平，没有像 CoCoOp 那样牺牲基类；
- 和预训练数据差别越大的数据集，提升越明显：EuroSAT HM +11.14、FGVCAircraft +8.76、DTD +3.31（相对 CoCoOp）；
- 在通用物体数据集上提升很小：Caltech101 +0.18、OxfordPets +0.15。

本项目复现用到的六个数据集的论文数值：

| 数据集 | Base | Novel | HM |
|---|---:|---:|---:|
| OxfordPets | 95.43 | 97.76 | 96.58 |
| DTD | 80.36 | 59.18 | 68.16 |
| Caltech101 | 97.74 | 94.36 | 96.02 |
| Flowers102 | 95.92 | 72.46 | 82.56 |
| EuroSAT | 94.07 | 73.23 | 82.35 |
| FGVCAircraft | 37.44 | 35.61 | 36.50 |

### 6.2 提示设计的消融（论文表 1，11 数据集平均）

这张表是理解 MaPLe 设计动机的关键：

| 变体 | Base | Novel | HM |
|---|---:|---:|---:|
| 浅层 MaPLe（J=1） | 80.10 | 73.52 | 76.67 |
| 只有深层视觉提示 | 80.24 | 73.43 | 76.68 |
| 只有深层文本提示 | 81.72 | 73.81 | 77.56 |
| 两侧都有，但各学各的（Independent V-L） | 82.15 | 74.07 | 77.90 |
| **MaPLe（两侧 + 耦合 + 深层）** | **82.28** | **75.14** | **78.55** |

逐行读：深层比浅层好（第 1 行 → 第 3 行）；文本提示比视觉提示更有效（第 2 行 vs 第 3 行）；
两侧都加比只加一侧好（第 4 行）；**加上耦合函数还能再涨 0.65 HM，主要涨在新类**（第 4 行 → 第 5 行）。

### 6.3 跨数据集迁移与域泛化

在 ImageNet 全部 1000 类上训练（这时 J=3、2 个 epoch），直接迁移到其他数据集：

- **跨数据集**（论文表 4）：10 个目标数据集平均 66.30%，高于 CoOp 63.88%、CoCoOp 65.74%；
- **域泛化**（论文表 5）：在 ImageNetV2 / Sketch / A / R 四个分布偏移版本上，比 CoOp、CoCoOp 持平或更好。

### 6.4 其他消融与效率

- **提示深度**：性能大体随深度增加而提高，J=9 最好；在已经成熟的深层特征里插入随机初始化的提示，会让结果更敏感。
- **提示长度**：越长，基类基本不变，新类下降，说明过拟合；所以选 2。
- **计算量**：FLOPs 只比 CoOp、CoCoOp 多 0.1%。推理速度远快于 CoCoOp（batch 100 时 1365 FPS 对 15 FPS），
  因为 CoCoOp 每张图都要重新编码一遍所有类别的文本。训练只需 5 个 epoch（CoCoOp 要 10 个）。
- **是不是靠参数多取胜**：作者做了 MaPLe†，让所有层共享一个耦合函数，参数少约 9 倍（0.41M），HM 仍有 78.11，
  依然优于以前的方法。

## 7. 能解决什么问题

| 问题 | MaPLe 的做法 | 效果 |
|---|---|---|
| CLIP 全量微调代价大、容易遗忘 | 冻结 CLIP，只训练 2.85% 的参数 | 每类 16 张样本、5 个 epoch 就能适配 |
| 只调一个分支，适配不完整 | 文本和视觉两侧同时加提示 | 图像特征也能随任务调整，类别更可分 |
| 两侧各学各的，缺少协同 | 耦合函数：视觉提示由文本提示生成，梯度互相传递 | 消融中新类 +1.07、HM +0.65 |
| 只在输入层加提示，调整能力有限 | 前 9 层每层一组新提示 | 深层比浅层 HM +1.9 |
| CoOp 在新类上过拟合，CoCoOp 推理慢 | 不依赖输入图片的静态提示 | 新类超过零样本 CLIP，推理速度和 CoOp 相当 |
| 和预训练分布差别大的领域效果差 | 视觉侧也能被调整 | EuroSAT、Aircraft、DTD 等数据集提升最大 |

## 8. 局限与值得注意的地方

以下几点有的来自论文本身，有的是本项目复现和分析时发现的，写论文时可以引用：

1. **新类上并不总是比零样本 CLIP 好。** 论文自己的数据：MaPLe 只在 6/11 个数据集的新类上超过 CLIP。
   比如 DTD 新类 59.18 < CLIP 59.90，Flowers 72.46 < 77.80，StanfordCars 74.00 < 74.89。
   训练过程仍然会损失一部分预训练知识。后续工作 PromptSRC（ICCV 2023，同一作者团队）正是针对这个问题加了正则化。
2. **耦合函数是线性的，视觉提示和图片无关。** 所有图片共用同一组视觉提示；
   而且对可训练的线性层而言，后面再乘一个静态缩放可以被它吸收，这是本项目第一阶段静态门控失败的根本原因。
3. **参数主要花在耦合函数上。** 3.55M 中 99.7% 是 9 个 512×768 的线性层；MaPLe† 说明大部分参数其实可以省掉。
4. **超参数对所有数据集固定**（J=9、长度 2、5 个 epoch、学习率 0.0035），在细粒度、样本少的数据集上可能不稳定。
   本项目在 FGVCAircraft 上发现，原版 MaPLe 在 5 个种子中有 1 个训练崩溃（HM 19.44），论文只报告了 3 个种子的平均值。
5. **复现有环境差异。** 论文用 A100 + PyTorch 1.9；本项目用 RTX 3090 + PyTorch 2.1.2，
   DTD 新类低约 3.3 个点，EuroSAT 基类低约 2.9 个点，详见 [BASELINE_REPRODUCTION_AUDIT.md](BASELINE_REPRODUCTION_AUDIT.md)。
